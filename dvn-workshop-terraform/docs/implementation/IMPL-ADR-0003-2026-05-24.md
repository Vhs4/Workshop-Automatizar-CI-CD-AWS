## Summary

Full rewrite of stack `02-eks-stack-ai` from scratch, incorporating four empirical constraints
that invalidated the previous version of this stack:

1. Account SCP blocks non-free-tier EC2 (t3.medium fails) — switched to `t4g.small` ARM.
2. K8s 1.31 is in extended support ($0.60/hr) — upgraded to 1.33 (standard support, $0.10/hr).
3. `bootstrap_cluster_creator_admin_permissions` is create-only — added `lifecycle.ignore_changes`.
4. Non-ASCII characters in AWS API descriptions cause validation failures — all descriptions use ASCII only.

Previous IMPL file for ADR-0003 (2026-05-24) is now superseded by this rewrite.

## Decisions Implemented (mirroring ADR-0003)

| Decision | Implementation |
|---|---|
| t4g.small ARM (account SCP constraint) | instance_types=["t4g.small"], ami_type="AL2023_ARM_64_STANDARD" in node group + tfvars |
| K8s 1.33 standard support | kubernetes_version="1.33" in tfvars |
| authentication_mode=API (no aws-auth ConfigMap) | access_config.authentication_mode="API" in eks.cluster.tf |
| bootstrap_cluster_creator_admin_permissions=false + lifecycle.ignore_changes | eks.cluster.tf: attribute set to false, lifecycle block ignores it to prevent cluster replacement |
| bootstrap_self_managed_addons=false | Set on aws_eks_cluster.this; 4 addons declared explicitly via aws_eks_addon |
| Pod Identity for vpc-cni (not IRSA) | aws_iam_role.vpc_cni with pods.eks.amazonaws.com trust; aws_eks_pod_identity_association.vpc_cni |
| pod-identity-agent first in addon order | aws_eks_addon.pod_identity_agent has no node group dependency; vpc_cni/coredns/kube_proxy depend on node group |
| KMS CMK for secrets + EBS | aws_kms_key.eks_secrets used in encryption_config and in launch_template EBS |
| IMDSv2 required on nodes | launch_template.metadata_options: http_tokens=required, hop_limit=1 |
| EBS gp3 20GiB encrypted | block_device_mappings in launch_template |
| CloudWatch log group before cluster | aws_cloudwatch_log_group.cluster in depends_on of aws_eks_cluster.this |
| Access Entries for admin | for_each=toset(var.cluster_admins) on aws_eks_access_entry.admin |
| upgrade_policy.support_type=STANDARD | Set on aws_eks_cluster.this |
| ASCII-only descriptions | All aws_security_group, aws_iam_role, aws_kms_key descriptions use ASCII only |
| Outputs for downstream stacks | 14 outputs defined; CA data marked sensitive=true |

## Rollback Plan

Full stack rollback (non-destructive resources only — KMS CMK enters pending deletion):

```bash
cd dvn-workshop-terraform/02-eks-stack-ai
terraform destroy -var-file="envs/production.tfvars"
```

Terraform dependency graph ensures correct destruction order:
addons -> pod_identity_association -> node_group -> access_entries -> cluster -> security_group -> kms + iam + cloudwatch_log_group

If KMS key needs to be preserved after destroy:
```bash
aws kms cancel-key-deletion --key-id <key-id> --region us-east-1
```

For partial failure during apply, do NOT fix on the fly:
1. Capture `terraform.tfstate` content and error message.
2. Report to human.
3. Run `terraform plan -var-file="envs/production.tfvars"` to assess drift.
4. Apply targeted fixes: `terraform apply -target=<resource> -var-file="envs/production.tfvars"`.
