## Lessons Learned / Gotchas

1. **EKS access entry takes ~10s to create** — the provider waits correctly; no custom timeout needed.
2. **`aws_iam_openid_connect_provider` `thumbprint_list` shows as `(known after apply)` in plan** — this is correct behavior; the provider populates it from AWS's CA library at apply time. Not a concern.
3. **S3 backend bucket name has account ID suffix** (`dvn-workshop-production-terraform-state-407295215751`) — the ADR cited `dvn-workshop-production-terraform-state` without the suffix. Always confirm from the existing stacks' `versions.tf`.
4. **`gh` CLI not in PATH** — it is installed at `/opt/homebrew/bin/gh` but not in the shell PATH used by the agent. Human must run GitHub variable configuration manually.
5. **`AmazonEKSEditPolicy` ARN uses literal `aws` partition** in the ARN (`arn:aws:eks::aws:...`) — this is an AWS-managed policy, not account-scoped. Using `data.aws_partition.current.partition` would be wrong here (only correct for account-scoped resources).
6. **Container name in both deployments is `app`** — confirmed by reading `k8s/youtubeliveapp/10-deployment.yaml` and `k8s/youtube-live-app/10-deployment.yaml`. The `kubectl set image` command uses `app=<image>` in both workflows.

## Rollback Plan

### If stack needs to be destroyed
```bash
# WARNING: destroys ALL CI/CD IAM resources — breaks all GHA deploys immediately

cd dvn-workshop-terraform/03-cicd-stack-ai
```

### If a deploy workflow fails mid-flight
The workflow itself handles rollback: the `Rollback on failure` step runs `kubectl rollout undo deployment/<x> -n youtube-live` and exits 1. Manual override: `kubectl rollout undo deployment/<x> -n youtube-live` from a machine with cluster admin credentials.
